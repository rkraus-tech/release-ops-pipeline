# Project Notes – release-ops-pipeline

## Phase 1 – Planning & repository setup
- Decisions: Jenkins runs natively (apt, systemd) on a dedicated Debian 13 VM `ops01` on the existing Proxmox host `pve01` – realistic always-on build server, Bash runs in the same OS as the deploy target. Docker on the ThinkPad was rejected (Windows/WSL quirks, not always on).
- Database: PostgreSQL instead of SQLite – real DB server with a least-privilege role and proper secret handling.
- Created empty GitHub repo first (no README/license via GitHub) to avoid unrelated histories on the first push; added a placeholder README locally.
- Folder structure: jenkins, scripts, sql, python, app, screenshots, docs (`.gitkeep` files because Git does not track empty folders).
- `.gitattributes` forces LF for all Linux-side files (*.sh, Jenkinsfile, *.py, *.sql). Reason: CRLF from Windows breaks Bash (`$'\r': command not found`). Verified with `git check-attr eol -- scripts/deploy.sh`.
- `.gitignore` excludes secrets (.env, .pgpass, keys), Python caches, runtime logs (except log-scanner samples) and unredacted screenshots (`screenshots/raw/`).
- Both files start with a comment line so a UTF-8 BOM (Windows PowerShell 5.1) cannot invalidate the first rule.

## Phase 2 – Pipeline VM on Proxmox
- Created VM 125 `ops01` on `pve01`: Debian 13 netinst, q35, 2 vCPU (type `host`), 4 GiB RAM, 32 GiB disk on `local-lvm` (VirtIO SCSI single, discard + SSD emulation), VirtIO NIC on `vmbr0`, QEMU guest agent enabled.
- VM ID 125 matches the planned IP 192.168.2.25 – naming convention for quick mapping between VM and address.
- CPU type `host` instead of the default `x86-64-v2-AES`: single-node setup, so live-migration compatibility is not needed; better performance for Java (Jenkins) and SSH.
- Discard + SSD emulation so deleted blocks are returned to the LVM-thin pool via TRIM.
- Installer choices: English system language (searchable error messages and logs), timezone Europe/Berlin (correct timestamps for the deploy history), German keyboard, hostname `ops01.home.arpa` (RFC 8375 home-network domain).
- No root password: root account locked, `sudo` installed automatically for user `robert` – every admin command is logged with the user name.
- Single partition without LVM: flexibility already comes from Proxmox (resize disk in Proxmox, grow the partition in Debian).
- Minimal headless install: only SSH server + standard system utilities, no desktop (smaller attack surface, less RAM, fewer updates).
- Static IP: `/etc/network/interfaces` changed from `allow-hotplug` + `inet dhcp` to `auto` + `inet static` (192.168.2.25/24, gateway 192.168.2.1). `auto` makes boot wait for the network. Backup created first (`interfaces.bak`).
- Enabled "Start at boot", ejected the installation ISO, verified the IP via the guest agent in the Proxmox summary, switched to SSH for all further work.

### Challenge: DNS lost after reboot
- Symptom: after reboot, `ping deb.debian.org` failed with "Temporary failure in name resolution", while `ping 192.168.2.1` worked.
- Diagnosis: `/etc/resolv.conf` header showed "Generated by dhcpcd". dhcpcd is still started at boot for IPv6 (`iface ens18 inet6 auto`) and rewrote the file – without any IPv4 nameserver.
- First fix attempt (`nohook resolv.conf` in `/etc/dhcpcd.conf`) did not work: `tail /etc/dhcpcd.conf` revealed a typo (`nohohook`), which dhcpcd silently ignores.
- Solution: corrected the line to `nohook resolv.conf`, wrote `/etc/resolv.conf` manually (`search home.arpa`, `nameserver 192.168.2.1`), verified after reboot.
- Lesson: always verify config changes after a reboot, and check the actual file content instead of assuming a command worked.

## Phase 3 – Jenkins & sample app
- Installed `openjdk-21-jre-headless` + `fontconfig` before Jenkins: current Jenkins LTS requires Java 21+; headless JRE because the server only runs Java and has no GUI; fontconfig is needed by Jenkins for rendering graphs.
- Added the official Jenkins LTS apt repository (`debian-stable`) with a dedicated keyring (`signed-by=/etc/apt/keyrings/jenkins-keyring.asc`) so the key is trusted only for this source. LTS instead of weekly for stability.
- `Ign: ... InRelease` during `apt update` is expected: the Jenkins repo provides `Release` + `Release.gpg` instead of `InRelease`; signature verified (no NO_PUBKEY).
- Jenkins runs as systemd service under the unprivileged `jenkins` user (least privilege), listening on port 8080. Note: Jenkins logs in UTC, systemd in local time.
- Unlocked with the one-time `initialAdminPassword`, installed suggested plugins (Pipeline, Git, Credentials, Timestamper, ...), created a personal admin account instead of the default `admin`.
- Installed nginx as deploy target, plus `curl` (HTTP checks) and `jq` (JSON parsing for the health check) – both missing in the minimal install.
- Release layout: `/opt/release-app/releases/<version>/` + symlink `/opt/release-app/current`. Switching the symlink is atomic; rollback = pointing the symlink back. Directory owned by `jenkins`, so deployments need no sudo.
- nginx site `release-app`: root `/opt/release-app/current`, `/health` serves `health.json` with `Cache-Control: no-store`, dedicated access/error logs (input for the Python log scanner). Disabled the default site, validated with `nginx -t`, applied with `reload` (no dropped connections).
- Expected `404` before the first release confirmed the new config was active.
- Sample app in `/app`: `VERSION` (single source of truth), `index.html` and `health.json` with placeholders (`__VERSION__`, `__BUILD__`, `__BUILT_AT__`) that the build stamps.
- Files written via `[IO.File]::WriteAllText` because Windows PowerShell 5.1 `Set-Content -Encoding utf8` adds a BOM, which breaks JSON parsing with `jq`.
